NotifyBridge V5.0 Complete
==========================

النسخة الأولى والحصرية • مفتوحة المصدر
--------------------------------------
NotifyBridge V5.0 هي النسخة الأولى والحصرية من مشروع NotifyBridge، وتم طرحها كمشروع مفتوح المصدر بهدف التعلم والتجربة والتطوير وبناء حلول مخصصة لربط إشعارات أجهزة Android بلوحة ويب.

فكرة المشروع
------------
يقوم تطبيق NotifyBridge على هاتف Android بقراءة إشعارات التطبيقات التي يختارها المستخدم، ثم إرسال بيانات الإشعار عبر اتصال HTTPS إلى API خاص بالمشروع. يستقبل خادم PHP البيانات ويتحقق من مفتاح API ثم يحفظها في قاعدة MySQL لتظهر في لوحة التحكم على الويب.

مسار العمل:
تطبيق Android → Notification Listener → HTTPS API → PHP → MySQL/MariaDB → لوحة NotifyBridge

محتويات الحزمة
--------------
- server/  : لوحة الويب، API، إدارة مفاتيح API، ملفات التثبيت وقاعدة البيانات.
- android/ : مشروع Android Studio الكامل لتوليد APK.

أهم المميزات
------------
- اختيار التطبيقات المراد متابعة إشعاراتها فقط.
- عرض اسم التطبيق وأيقونته داخل تطبيق Android.
- إرسال الإشعارات إلى لوحة الويب عبر API Key.
- لوحة تحكم عربية متجاوبة.
- إدارة أكثر من API Key: إنشاء، عرض، نسخ، تفعيل، تعطيل وحذف بحسب صلاحيات النظام.
- تسجيل الإشعارات والأجهزة والتطبيقات وسجل النشاط.
- اختبار الاتصال من تطبيق Android.
- عرض كود HTTP ونتيجة آخر عملية إرسال للمساعدة في التشخيص.
- اختبار إشعارات من لوحة الويب.
- بحث وتحديث للبيانات من الواجهة.
- دعم RTL.
- تصميم أبيض وأزرق سماوي.
- الكود متاح للتعديل والتطوير.

متطلبات تشغيل خادم الويب
------------------------
1) استضافة أو VPS يدعم PHP وMySQL/MariaDB.
2) يوصى باستخدام PHP 8.x.
3) PDO + PDO MySQL مفعّلان.
4) دعم mbstring لأن الـAPI يتعامل مع النصوص العربية ويستخدم mb_substr.
5) قاعدة MySQL أو MariaDB مع صلاحية إنشاء الجداول والقراءة والكتابة والتحديث.
6) شهادة SSL ورابط HTTPS صالح.
7) السماح بطلبات HTTP/HTTPS الخارجية الواردة من تطبيقات Android.
8) السماح بطلبات POST إلى /api/push.php واستقبال application/json.
9) السماح بتمرير Header مخصص باسم X-API-Key إلى PHP.
10) عدم وجود حماية تمنع العملاء غير المتصفحات أو تتطلب JavaScript/Cookies قبل السماح بالوصول إلى الـAPI.

مهم جداً بخصوص الاستضافة
------------------------
ليست كل الاستضافات المجانية مناسبة لهذا المشروع. قد يفتح الموقع بصورة طبيعية في المتصفح، بينما تمنع الاستضافة طلبات API القادمة من تطبيق Android أو أدوات خارجية.

قبل اعتماد أي استضافة تأكد من أنها:
- تسمح لتطبيق Android بإرسال POST مباشرة إلى رابط HTTPS.
- لا تفرض Browser Verification أو JavaScript Challenge على مسار API.
- لا تمنع أو تحذف X-API-Key Header.
- تسمح باستقبال JSON Request Body.
- لا تعيد 400/403 لمجرد أن الطلب قادم من تطبيق وليس من متصفح.

إذا كان الموقع يعمل لكن تطبيق NotifyBridge يعرض HTTP 400 أو HTTP 403 ولا تصل البيانات إلى قاعدة البيانات، فافحص قيود الاستضافة أولاً قبل تعديل التطبيق.

متطلبات تطبيق Android
---------------------
- هاتف Android 8.0 أو أحدث (minSdk 26).
- اتصال إنترنت.
- منح NotifyBridge صلاحية Notification Access يدوياً من إعدادات Android.
- رابط HTTPS صحيح لملف api/push.php.
- API Key فعال من لوحة التحكم.

متطلبات بناء APK
----------------
- Android Studio حديث.
- Android SDK 35.
- المشروع يستهدف Android SDK 35.
- Java/Kotlin Target في المشروع مضبوط على 17.
- إذا طلب Android Studio اختيار Gradle JVM، استخدم JDK/JVM متوافقاً مع Gradle المستخدم في المشروع؛ JVM 21 مناسب للبيئة التي اختُبر عليها المشروع، وتجنب JVM 25 مع Gradle 8.7.
- اتصال إنترنت عند أول Build لتنزيل Dependencies إذا لم تكن موجودة محلياً.

طريقة تثبيت الويب - تثبيت جديد
------------------------------
1) أنشئ قاعدة MySQL/MariaDB فارغة.
2) ارفع محتويات مجلد server إلى الاستضافة.
3) افتح install.php من المتصفح.
4) أدخل بيانات قاعدة البيانات وبيانات حساب المدير.
5) أكمل التثبيت حتى يتم إنشاء الجداول والإعدادات المطلوبة.
6) ادخل إلى لوحة التحكم.
7) افتح إدارة API واعرض المفتاح الذي تم إنشاؤه أو أنشئ API Key جديداً.
8) بعد التأكد من نجاح التثبيت، احذف أو عطّل install.php إذا كانت بيئة النشر تتطلب ذلك، ولا تعِد تشغيل التثبيت على قاعدة مستخدمة.

إعداد تطبيق Android
-------------------
1) افتح مجلد android في Android Studio.
2) انتظر Gradle Sync حتى يكتمل.
3) ابنِ APK وثبته على هاتف Android.
4) افتح NotifyBridge.
5) أدخل رابط الاستقبال بالشكل التالي:
   https://YOUR-DOMAIN/api/push.php
6) أدخل API Key فعالاً من لوحة التحكم.
7) احفظ الإعدادات.
8) اضغط اختبار الاتصال بالسيرفر.
9) إذا ظهر HTTP 200، انتقل إلى صلاحية قراءة الإشعارات وفعّل NotifyBridge.
10) ارجع إلى التطبيق وحدد التطبيقات المطلوب متابعتها.
11) عند وصول إشعار جديد من تطبيق محدد، يقوم NotifyBridge بمحاولة إرساله إلى السيرفر.

اختبار النظام
-------------
- اختبار الاتصال من Android يجب أن يصل إلى API ويعطي نتيجة HTTP واضحة.
- عند وصول إشعار حقيقي، راقب "آخر إشعار" و"آخر نتيجة إرسال" داخل التطبيق.
- راجع جدول notifications ولوحة الويب للتأكد من وصول البيانات.
- يمكن استخدام اختبار الإشعار الموجود في لوحة الويب لفحص واجهة العرض.

أكواد HTTP الشائعة
------------------
HTTP 200 : تم قبول الطلب من API.
HTTP 400 : طلب غير صالح؛ إذا كان الرد صفحة HTML وليس JSON فقد يكون الرفض من خادم/حماية الاستضافة قبل PHP.
HTTP 401 : API Key مفقود أو غير صحيح أو غير فعال.
HTTP 403 : غالباً منع من الاستضافة/WAF أو سياسة وصول.
HTTP 405 : تم فتح endpoint بطريقة غير POST.
HTTP 422 : حقل مطلوب مفقود من البيانات.
HTTP 500 : خطأ داخل PHP/قاعدة البيانات أو إعدادات الخادم.

ملاحظات الأمان والخصوصية
------------------------
- إشعارات الهاتف قد تحتوي معلومات خاصة؛ استخدم المشروع فقط على أجهزة وحسابات تملكها أو لديك إذن واضح لإدارتها.
- لا تشارك API Keys علناً.
- استخدم HTTPS دائماً.
- استخدم كلمات مرور قوية للوحة الإدارة وقاعدة البيانات.
- أنشئ API Key منفصلاً لكل جهاز عند الحاجة حتى تستطيع تعطيل جهاز دون التأثير على الآخرين.
- ألغِ Notification Access من إعدادات Android إذا لم تعد تريد للتطبيق قراءة الإشعارات.
- راجع سياسة الخصوصية ومتطلبات الإفصاح المناسبة قبل توزيع APK على مستخدمين آخرين.

استكشاف الأخطاء
---------------
1) التطبيق لا يرى الإشعارات:
   - تحقق من Notification Access.
   - تأكد أن التطبيق المطلوب محدد داخل NotifyBridge.

2) التطبيق يلتقط الإشعار لكن لا يظهر في الموقع:
   - راقب نتيجة HTTP داخل NotifyBridge.
   - تأكد من رابط push.php وAPI Key.
   - افحص قيود الاستضافة وWAF.
   - تحقق من قاعدة البيانات والجداول.

3) HTTP 401:
   - أنشئ/فعّل API Key من لوحة التحكم وأعد إدخاله في الهاتف.

4) HTTP 400/403 مع صفحة HTML:
   - هذا مؤشر محتمل على أن الطلب تم رفضه قبل الوصول إلى push.php؛ اختبر على استضافة تسمح بطلبات API الخارجية.

5) Android Studio يرفض البناء بسبب JVM:
   - لا تستخدم JVM 25 مع Gradle 8.7. اختر JVM 21 أو إصداراً متوافقاً.

6) Android resource linking و hintTextColor:
   - الخاصية الصحيحة في XML هي android:textColorHint وليست android:hintTextColor.

7) OkHttp code():
   - مع OkHttp المستخدم في المشروع استخدم response.code وليس response.code().

ملاحظات للمطورين
----------------
- API الرئيسي: server/api/push.php
- التطبيق يرسل JSON عبر POST.
- المصادقة تتم باستخدام X-API-Key.
- لا تغيّر applicationId بعد نشر التطبيق في متجر رسمي إلا وأنت مدرك أن Android/المتجر قد يتعامل معه كتطبيق مختلف.
- عند تطوير قاعدة البيانات لإصدار جديد، يفضّل إنشاء Migration/Upgrade بدلاً من إعادة استيراد قاعدة التثبيت فوق بيانات المستخدمين.

تنبيه
-----
NotifyBridge أداة تقنية لنقل الإشعارات التي يختار المستخدم السماح لها. نجاح الربط يعتمد أيضاً على نظام Android، الشبكة، إعدادات الخادم وسياسة شركة الاستضافة. وجود PHP وMySQL وحدهما لا يعني بالضرورة أن الاستضافة تسمح بطلبات API من تطبيقات Android.
